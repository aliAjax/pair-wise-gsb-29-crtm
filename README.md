# 城市末端配送模拟 — 同址订单合并与骑手时段释放台

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus、Leaflet
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则自检：`npm run check:rules`（36 项判定用例，纯 node 运行）

## 业务规则

1. **同址订单合并**：地址相同、配送时段相同、骑手相同且双方均为「未送达」时，才能并入主记录。
   - 并入后主记录的**原骑手、距离、备注不变**，被并入订单号登记到主记录。
   - 不同骑手、不同时段、不同地址、任一方已送达（冻结）时**不得合并，输入原样保留**，并回报冲突（地址 / 骑手 / 时段 / 原值）。
   - 未分配单不能作为并入对象；录入新单时若满足合并条件会自动并入。
2. **骑手时段释放**：骑手 × 时段为一格占用，合并后同格只记一次。
   - 改派时先释放原骑手占用，再占用新骑手时段；新时段已被他人占用则拒绝改派、原值全部保留。
   - 标记送达即释放占用；撤回派单回到「未分配」并释放。
3. **已送达冻结**：已送达记录不可直接改派或合并；后续调整**不修改原件**，而是生成同订单号的新版本（v2、v3…），并在交接记录中留痕原因与字段差异（原值 → 新值）。新版本若占用冲突则整条不落地。
4. **刷新一致性**：「刷新校验」重新读取 localStorage，核对订单、占用、交接记录三者一致；重复占用、缺送达时间、交接断链等冲突会带地址、骑手、时段和原值列出。

## 分层结构（资料 / 判定 / 页面分开）

```
src/
├─ data/orders.ts        # 资料层：类型、常量、种子订单、localStorage 读写
├─ rules/dispatch.ts     # 判定层：纯函数（合并/占用/改派/送达/交接/审计），无 DOM 依赖
├─ stores/dispatch.ts    # 编排：Pinia action 串起资料与判定，变更即落盘
├─ utils/format.ts       # 页面展示工具
└─ App.vue               # 页面层：录入、占用台、订单清单、交接记录、弹窗与冲突提示
scripts/                 # 判定层自检脚本
```

数据默认保存在浏览器 localStorage（`hxwlfront-15-last-mile-console`），页面可一键重置演示资料。
