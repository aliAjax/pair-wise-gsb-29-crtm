# 同址订单合并与骑手时段释放台（城市末端配送模拟）

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 分层结构（订单资料、判定与页面分开）

- `src/data/catalog.ts` —— **订单资料层**：骑手名册、配送时段、字段标签、演示种子数据，不含任何判定规则。
- `src/logic/core.ts` —— **判定层**：纯函数，集中所有业务规则，不碰 localStorage、时间和随机数，可直接单测。
- `src/stores/desk.ts` —— **状态层**：Pinia + localStorage 持久化，调用判定层并给冲突补 id/时间。
- `src/components/*` + `src/App.vue` —— **页面层**：录入、台账、合并台、占用/释放台、交接台、冲突板，只做交互与展示。
- `src/types.ts` —— 领域模型。

## 核心规则

1. **同址订单合并**
   - 必须同时满足：地址相同、配送时段相同、骑手相同、主记录与候选均为未送达的活跃记录。
   - 合并后沿用主记录的骑手、距离、备注，候选不再参与统计；同骑手同时段的占用**只记一次**。
   - 不同骑手 / 已送达冻结 / 地址或时段不一致：一律拒绝，**保留全部输入**，并在冲突板指出地址、骑手、时段和原值。
2. **骑手时段释放**
   - 改派前先释放原骑手在原时段的占用，再登记新骑手占用；新骑手该时段已被别的地址占用时拒绝并保留原值。
   - 送达后记录冻结为 v1 并释放骑手时段；也可在释放台手动释放（订单退回未分配）。
3. **冻结与交接**
   - 已送达记录冻结，页面不允许直接改；后续调整必须填写交接原因，另存为 v2、v3…… 新版本，保留冻结原值快照。
4. **刷新一致**
   - 订单、占用台账、交接记录持久化在 localStorage；每次刷新自动审计三方一致性，异常会带地址、骑手、时段、原值展示在冲突板。

## 演示数据可验证的场景

- `DM-1001 / DM-1002`：同址、同时段、同骑手（骑手A，10:00-12:00），可直接合并。
- `DM-1003`：同址同时段但是**骑手B**，勾入合并会被拒并指出骑手差异与原值。
- `DM-1006`：已送达冻结，合并被拒；调整只能在交接台另存 v2。
- 把在配订单改派到已被其他地址占用的骑手时段，可看到占用冲突；送达或释放后占用台账实时更新。
